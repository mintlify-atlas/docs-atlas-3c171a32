The Unified Font Object (UFO) is an open, cross-platform format for storing font source data. Designed around plain-text files and a simple directory structure, UFO is readable by humans and tools alike — making it ideal for version control, collaboration, and long-term archival.

## The UFO Design Philosophy

UFO is built on three core principles that have guided every version of the specification:

- **Human readable and editable** — All data is stored as plain text (XML, property lists, OpenType feature code). Any file can be opened and edited with a text editor.
- **Application independent** — The format is not tied to any single font editor or toolchain. Any tool that understands the spec can read and write UFO files.
- **No unnecessary duplication** — Data is stored once and referenced where needed, keeping files clean and unambiguous.

## Quick Overview: UFO 3 Structure

A UFO 3 package is a `.ufo` directory containing these files and directories:

```
MyFont.ufo/
├── metainfo.plist        # Format version and creator tool
├── fontinfo.plist        # Font names, metrics, OpenType table data
├── groups.plist          # Glyph group definitions (including kerning groups)
├── kerning.plist         # Horizontal kerning pairs
├── features.fea          # OpenType feature definitions
├── lib.plist             # Arbitrary custom data
├── layercontents.plist   # Glyph layer directory mapping
├── glyphs/               # Default glyph layer
│   ├── contents.plist    # Glyph name → filename mapping
│   ├── layerinfo.plist   # Layer metadata
│   └── *.glif            # Individual glyph files (XML)
├── images/               # PNG images referenced by glyphs
└── data/                 # Arbitrary custom data (binary or structured)
```
