The `fontinfo.plist` file contains information about the font itself — including naming, dimensions, and table-specific data for OpenType, PostScript, and WOFF. This file is an XML Property List and is **optional**; not all keys are required for a valid UFO. Authoring tools should read and write only the keys they understand, and preserve unknown keys they encounter.

<Note>
  All fields in `fontinfo.plist` are optional. Omitting a key is valid; authoring tools should not require any particular field to be present.
</Note>

## Bit Numbers

Throughout this specification, several fields reference **bit numbers** — lists of integers indicating which bits should be set in the corresponding binary font field. For example, given a fictional specification field `foo` with bits 0 (Left), 1 (Right), 2 (Up), and 3 (Down), storing "Left" and "Up" looks like this in `fontinfo.plist`:

```xml
<key>fictionalFontSpecFoo</key>
<array>
  <integer>0</integer>
  <integer>2</integer>
</array>
```

The integer values in the list correspond directly to the bit positions defined in the referenced specification for that field.

## OpenType gasp Table Fields

<ParamField path="openTypeGaspRangeRecords" type="list">
  A list of gasp Range Records. These must be sorted in ascending order based on the `rangeMaxPPEM` value of each record.
</ParamField>

### gasp Range Record Format

Each record in `openTypeGaspRangeRecords` is a dictionary with the following keys:

<ParamField path="rangeMaxPPEM" type="non-negative integer">
  The upper limit of the range, in PPEM. The final record should use `65535` (0xFFFF) as defined in the OpenType gasp specification. Corresponds to the `rangeMaxPPEM` field of the `GASPRANGE` record.
</ParamField>

<ParamField path="rangeGaspBehavior" type="list">
  A list of bit numbers indicating the flags to be set. Corresponds to the `rangeGaspBehavior` field of the `GASPRANGE` record.

  | Bit | Flag |
  |-----|------|
  | 0   | GASP_GRIDFIT (0x0001) |
  | 1   | GASP_DOGRAY (0x0002) |
  | 2   | GASP_SYMMETRIC_GRIDFIT (0x0004) |
  | 3   | GASP_SYMMETRIC_SMOOTHING (0x0008) |
</ParamField>

## OpenType head Table Fields

<ParamField path="openTypeHeadCreated" type="string">
  Creation date, expressed as `"YYYY/MM/DD HH:MM:SS"` in UTC. Month must be 1–12, day must be 1–end of month, hour 0–23, minute and second 0–59.
</ParamField>

<ParamField path="openTypeHeadLowestRecPPEM" type="non-negative integer">
  Smallest readable size in pixels. Corresponds to the OpenType `head` table `lowestRecPPEM` field.
</ParamField>

<ParamField path="openTypeHeadFlags" type="list">
  A list of bit numbers indicating the flags. The bit numbers are listed in the OpenType head specification. Corresponds to the `head` table `flags` field.
</ParamField>

<Info>
  Several head table fields are derived or calculated by authoring tools: `fontRevision` comes from `versionMajor`/`versionMinor`; `checkSumAdjustment`, `magicNumber`, `modified`, `xMin/yMin/xMax/yMax`, `indexToLocFormat`, and `glyphDataFormat` are all set by the tool. `macStyle` is derived from `styleMapStyleName`.
</Info>

</ParamField>

</ParamField>

## WOFF Data

Many WOFF fields can be populated from generic elements, but since WOFF is a wrapper format they may not always be duplicated. All WOFF fields are optional.

<ParamField path="woffMajorVersion" type="non-negative integer">
  Major version of the font for WOFF.
</ParamField>

<ParamField path="woffMinorVersion" type="non-negative integer">
  Minor version of the font for WOFF.
</ParamField>

<ParamField path="woffMetadataUniqueID" type="dictionary">
  Identification string. Must follow the WOFF Metadata Unique ID Record structure: `{ "id": string }`.
</ParamField>

<ParamField path="woffMetadataVendor" type="dictionary">
  Font vendor metadata. Required key: `name` (string). Optional keys: `url`, `dir` (`ltr` or `rtl`), `class`.
</ParamField>

<ParamField path="woffMetadataCredits" type="dictionary">
  Font credits. Contains a `credits` list; each credit has a required `name` and optional `url`, `role`, `dir`, `class`.
</ParamField>

<ParamField path="woffMetadataDescription" type="dictionary">
  Font description. Optional `url` key plus a `text` list of WOFF Metadata Text Records.
</ParamField>

<ParamField path="woffMetadataLicense" type="dictionary">
  Font license. Optional `url` and `id` keys plus a `text` list of WOFF Metadata Text Records (may be empty).
</ParamField>

<ParamField path="woffMetadataCopyright" type="dictionary">
  Font copyright. Contains a `text` list with at least one WOFF Metadata Text Record.
</ParamField>

<ParamField path="woffMetadataTrademark" type="dictionary">
  Font trademark. Contains a `text` list with at least one WOFF Metadata Text Record.
</ParamField>

<ParamField path="woffMetadataLicensee" type="dictionary">
  Font licensee. Required key: `name`. Optional keys: `dir`, `class`.
</ParamField>

<ParamField path="woffMetadataExtensions" type="list">
  A list of WOFF Metadata Extension Records. Must contain at least one record. Each record has optional `id`, a `names` list, and an `items` list (at least one item required).
</ParamField>

### WOFF Metadata Text Record

Text records are used inside multiple WOFF metadata structures:

<ParamField path="text" type="string">
  The text content. Required.
</ParamField>

<ParamField path="language" type="string">
  Language tag. Corresponds to the `xml:lang` attribute. Optional.
</ParamField>

<ParamField path="dir" type="string">
  Writing direction: `ltr` or `rtl`. Optional.
</ParamField>

<ParamField path="class" type="string">
  Class tokens. Optional.
</ParamField>

<Note>
  WOFF metadata elements that allow `<div>` and `<span>` children must have those stored as raw escaped HTML text in the appropriate `text` field. For example:

  ```xml
  <key>woffMetadataDescription</key>
  <dict>
    <key>text</key>
    <array>
      <dict>
        <key>language</key>
        <string>en</string>
        <key>text</key>
        <string>&lt;div&gt;&lt;span dir=&quot;ltr&quot;&gt;description&lt;/span&gt;&lt;/div&gt;</string>
      </dict>
    </array>
  </dict>
  ```
</Note>

## Guidelines

<ParamField path="guidelines" type="list">
  A list of guideline definitions that apply to all glyphs in all layers in the font. This attribute is optional.
</ParamField>

### Guideline Format

Each guideline is a dictionary with the following keys:

<ParamField path="x" type="integer or float">
  The x coordinate. Optional if `y` is provided and `angle` is not provided. Omitting both `x` and `angle` creates a horizontal guideline.
</ParamField>

<ParamField path="y" type="integer or float">
  The y coordinate. Optional if `x` is provided and `angle` is not provided. Omitting both `y` and `angle` creates a vertical guideline.
</ParamField>

<ParamField path="angle" type="integer or float">
  Angle of the guideline, in counter-clockwise degrees from the horizontal, between 0 and 360. Must not be specified if neither `x` nor `y` is specified.
</ParamField>

<ParamField path="name" type="string">
  An arbitrary name for the guideline. Optional.
</ParamField>

<ParamField path="color" type="string">
  Color to apply to the guideline, following the UFO color definition format. Optional.
</ParamField>

<ParamField path="identifier" type="string">
  Unique identifier for the guideline within `fontinfo.plist`. Optional, but once assigned must not be unnecessarily removed or changed. Must be unique within the `fontinfo.plist` guidelines list.
</ParamField>

The guideline extends along `angle` to infinity in both directions from the point defined by `x` and `y`.
